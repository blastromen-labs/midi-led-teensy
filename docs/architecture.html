System overview

A DAW sends USB MIDI to the Teensy. The firmware maps notes and control changes to LED state, reads pre-rendered RGB frames from SD card or a serial stream, composites multiple visual layers, and pushes pixels to the physical matrix via OctoWS2811 DMA.

Logical display

5 columns × 3 rows of 8×32 pixel panels, wired in a serpentine pattern. Logical coordinates (x, y) map to physical LED indices via mapXYtoLedIndex().

Software modules

src/latest.ino is a single-file firmware organized into labeled sections:

  • ConfigurationDisplay dimensions, MIDI channel/CC constants, timing, buffer sizes

  • Coordinate / colormapXYtoLedIndex, applyHSVAdjustments, sampleLayer, mapCCScale

  • MIDI handlersPer-channel note/CC handlers + dispatchNoteEvent
  • Media I/OstartVideo, startImage, handleSDVideo, handleSerialVideo
  • CompositingupdateLEDs() — full layer stack per pixel
  • Setup / loopInit, main event loop, dirty-flag driven refresh

USB device name is configured separately in src/name.c (Teensy requirement).

Runtime loop

// Simplified main loop
void loop() {
  while (usbMIDI.read());          // drain MIDI queue → handlers update state

  if (Serial.available())
    handleSerialVideo();             // fast path: direct setPixel + show
  else if (serial timeout)
    clearScreen();                 // fall back to SD video
  else
    handleSDVideo();                 // read next frame into frameBuffer

  if (ledStateChanged && !leds.busy()) {
    updateLEDs();                    // composite all layers
    leds.show();
    ledStateChanged = false;
  }
}

Dirty-flag refresh

MIDI handlers and SD video set ledStateChanged = true. The compositor runs only when state changed and the DMA driver is idle — avoids redundant full-frame work.

Serial vs SD priority

When a serial stream is active, SD compositing is bypassed. After 1 s of no serial data, the screen clears and SD playback resumes.

Note dispatch

Every note on/off calls dispatchNoteEvent(), which fan-outs to all six handlers. Each handler early-returns if the channel doesn't match — simple and extensible.

Layer compositing

updateLEDs() iterates every pixel (x, y), maps to a physical LED index, and resolves color top-down:

5 Strobe overlay — strobeActive[] per-LED mask, highest priority
4 Legacy equal-RGB blocks — bypasses blending when R=G=B > 0
3 LED blocks — groupStates[], independent per-channel HSV
2 Image — alpha blend over video, scale/offset/HSV/velocity brightness
1 Video — bottom layer from frameBuffer, threshold + HSV + mirror/scale

Key helpers

FunctionPurpose
sampleLayer()Scale, offset, optional mirror → sample RGB from buffer
applyHSVAdjustments()FastLED HSV transform on video/image/strobe
perceivedBrightness()Luminance threshold to suppress noise pixels
setGroupColor()Write B/R/G to a 64-LED group

Serial fast path: handleSerialVideo() writes pixels directly, skipping the layer stack for maximum throughput.

Media pipeline

SD card video

Raw RGB frames stored as FRAME_BYTES (11,520 bytes) per frame. Note-on on ch 3 looks up video_map.txt, opens /video/{bank}/{file}.bin, streams frames at ~30 FPS with speed/direction/loop controls.

handleSDVideo() manages timing, reverse seek, and looping via seekToLastFrame().

SD card image

Single-frame .bin loaded into imageBuffer. Note-off clears the layer. Velocity sets per-mapping brightness used during alpha blending.

Serial stream

2 Mbaud USB serial receives full frames into serialBuffer, copies to frameBuffer, maps XY → LED, applies brightness threshold, and calls leds.show() immediately.

Bank system

CC 20 on ch 3 or 4 selects bank 0–127. Mappings are filtered by (note, bank). CC and note-on can arrive in the same DAW tick — bank is set before lookup.
